# 高报点轨迹 M-R1 离线对照（2026-11-04）

## 结论

当前实际 ResampledMotion / M-R1 源码对完整高报点轨迹与隔点保留轨迹给出不同的中间重建位置和整数位移序列。额外样本会参与重建及量化，不是仅增加接收计数。本批数据各版本最终累计整数位移相同，差别主要在运动过程。

这不证明完整轨迹更接近物理手指真值，不证明更平滑、手感更好或端到端延迟更低。隔点保留也不等同于手机切到真实120Hz后产生的数据。完整记录本身含噪声及长间隔。

## 方法

任务：20261104-sampling-offline-replay-r2。使用20261104-sampling-stability-r1的三条原始getevent，分别含9833、8169、7979个完整单指报告。以SYN_REPORT分组、跟踪坐标未变化轴、保留DOWN/UP与全部时间间隔，明确拒绝多接触和SYN_DROPPED。完整版本和两个不同相位的隔点MOVE版本共3种输入。

- 复用生产 ResampledMotion、CanonicalPositionQuantizer 源码，通过测试程序集显式 --sampling-replay 入口调用；没有重写一个代替生产的运动算法。
- 固定 M-R1、M8、1ms模拟调度、灵敏度12/12、Q0-C。保留24ms/120ms历史账本参数但不做位置卷积。每次非零输出仅累加在内存，未创建真实Runtime、MotionClock、UDP或原生输出设备。
- 原始驱动XY乘0.01作为竖屏像素坐标的近似映射；这是基于该机坐标范围的模型假设，未保存逐点Android MotionEvent坐标，不把它称为实际回调流。
- 每种输入测试及时到达、每8ms聚合到达、每16ms聚合到达三种模型，共3轨迹×3输入×3到达模型=27组。聚合模型为ceil(样本时间/周期)×周期，DOWN时间为0。同一时刻按顺序提交，再处理到期Tick。8/16ms是人为模型，不是本机网络测量结果。
- 独立参照使用已到达节点的因果线性轨迹，明确模拟暂停后重新等待下一个调度边界；不会预先使用尚未到达的未来节点。9个完整轨迹/到达组合与生产重建位置的最大差异均小于2e-12鼠标计数。
- 指标逐1ms、覆盖整个接触和完成边界，含所有停顿；RMS/P95/最大位置差是各降采版本相对于同一到达模型的完整版本，不是相对手指真值的误差。鼠标计数不直接等同显示器像素或游戏角度。

下表范围表示两种降采相位，保留所有DOWN与UP最终坐标：

第一条轨迹重建位置差P95为3.036–3.598计数，第二条1.875–3.060计数，第三条3.000–3.076计数。输出变化比例只表示某个时隙的整数dx/dy是否不同，不能解释为相同比例的精度、流畅度或延迟提升。

各轨迹所有9种组合的最终整数累计位移分别为(605,-160)、(243,-82)、(602,6)，与真实最终目标各轴残差均小于1计数。该一致性是本批数据的观察，不是所有轨迹/调度下整数终点必须完全相等的一般定理。

## 人为到达抖动

完整轨迹在8ms聚合模型中LateSamples为0；16ms聚合模型中分别4914、4089、3972个样本迟于其映射播放时刻，约占一半。此结果说明固定M8时间线在到达延迟超过余量时会出现迟到；它不是实际手机网络迟到率。

同一8ms聚合模型内，第一/第三条轨迹降采后的RMS位置差约7计数，高于及时到达条件约2计数。输入节点密度和到达分发时刻均影响输出；仅凭“Receiver接受了全部样本”不能确认所有细节都及时发挥作用。
