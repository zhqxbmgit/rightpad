## 使用与输入归属

- 在菜单用途中，一个有效 Mode DOWN 切换开关。保持接触、重复/重传/迟到报文和
  正常 UP 不再次切换。打开接触不进入菜单鼠标或原单键输出。
- 中央固定半径 **12 DIP**（含边界）没有选中；六个动作之外不增加关闭按钮。
  中央点按消耗，不输出、不关闭。越过中性区后只按相对打开锚点的方向选槽；
  间隙、外圈之外、装饰按钮之外均有效，没有距离上限，抬手或移出不会关闭。
- 菜单打开期间，手机鼠标区移动仍使用原 Motion/HID 鼠标路径：当前选择的 Motion
  引擎、正式 SensitivityX/Y、重建、量化和现有输出设备；每个已接受输入包只进入该
  移动处理一次。游戏因此可以收到鼠标移动，视角可能随之移动。没有菜单专用速度、
  DPI 位移倍数、补偿、预测或另一套操作指针。打开位置固定为视觉中心与选择锚点，
  打开不跳光标，也不平移锚点。
- 菜单只读取实际 Windows 系统光标进行高亮与点按判定。位置由 `GetCursorPos`
  读取；不再检查光标可见性/抑制标志，也不再读取或比较 `ClipCursor` 范围。
  Motion 是异步输出，菜单在既有维护循环中持续读取实际位置（约每 10 ms 及收包时），
  不会只在收到手机包时读取一次便停止更新。点按重新读取实际位置：已绑定方向执行
  该绑定的一次真实键盘或手柄按下/释放（完成后的确认与自动关闭见下节）；未绑定
  方向提交一次确认后自动关闭（见下节）；中央/中性区不动作。六方向使用同一
  Select 算法，角度从上方向起顺时针分六等份；30/90/150/210/270/330 度平分线归
  顺时针槽位。角度舍入到 10 位小数稳定数学边界，非自适应、无吸附、无预测。
- **已绑定槽位动作完成、确认振动与自动关闭（2026-10-21）**：一次有效点按绑定槽位后，
  Receiver 先提交该绑定的一次按下，再按原 25 ms 最小可见时间完成一次释放；只有
  **按下与释放都确实完成后**，才通过既有 Haptic Feedback v1 通道提交一次与原普通
  触控板成功单击完全相同的手机确认（相同 24 字节 RPHF、Sender run、原始 UP 身份、
  Android CONFIRM 与去重），随后关闭菜单。不新增协议、服务、设置、手势、振动参数
  或 Android 接收逻辑。
- **未绑定槽位有效点按（2026-10-22）**：`Selected==null` 的槽位不再“无反馈、
  不关闭”。一次有效点按先置本次打开周期的接纳标志，再以触发该点按的合格 UP
  `(SenderRunId, SessionId, Sequence)` 通过同一 Haptic Feedback v1 通道提交一次
  与原普通触控板单击完全相同的确认（相同 RPHF、Sender run、Android CONFIRM 与
  去重），然后立即关闭菜单。不提交键盘键、手柄按钮或普通鼠标点击，不伪造按下，
  不需要 25 ms 等待；反馈只做既有有界非阻塞入队，失败只记
  `mode_menu_feedback_error`，不重放、不阻止关闭。已绑定与未绑定选择共用“每个
  打开周期最多接纳一次”的门。
  - 已绑定确认只来自“有效绑定槽位”的真实完成动作；未绑定确认只来自有效未绑定
    槽位的一次合格点按。中央 12 DIP 中性区、导航移动、落指与抬手、Mode 按钮
    开关和手动关闭都不发确认。
  - 同一打开周期只执行/接纳这一项槽位动作（未绑定计入）。第一次有效点按被接纳后，
    后续点按不再排队；重传、重复包、迟到包和旧 UP 不会再次执行、再次确认或补出
    普通点击。原串行动作队列及 16 项上限已删除。
  - 确认是尽力而为的副作用：只做既有有界队列的非阻塞入队，不等待手机确认或实际
    振动结束就关闭；发送/执行失败只记录，不重放按键、不阻塞关闭和普通输入。
  - 输出失败仍走既有故障处理与安全释放，不发成功确认，不重试槽位动作。
  - 手动关闭（再次点 Mode）、断线、租约、配置变化、故障与呈现超时同样释放当前
    脉冲并且不发成功确认；自动关闭与这些路径共用同一把锁与生命周期，不使用跨代次
    异步回调，因此旧完成回调不可能关闭后来重新打开的菜单或给失效动作补发反馈。
  - 自动关闭清理本次菜单接触（`menu_exit`），不轮换 Mode 接触代次，Android 无需
    重新同步；关闭后普通输入从下一次新 DOWN 恢复。
- 菜单点按在普通单击/双击拖动产生鼠标按钮事件之前完成分流：菜单期间普通
  GestureProcessor 不接收这些包，因此中央、未绑定方向和点按都不会泄漏普通
  鼠标左键，也不会进入双击拖动。菜单不新增系统 Hook，不采用“先发左键再拦截”。
- 关闭不发送 Esc、暂停键、取消键或鼠标点击。菜单不是暂停游戏功能。

UdpReceiver 在正常 Motion/Gesture 之前，把序号已接受的 Touch 包交给 ModeSession
的输入归属门。菜单打开时，该门把同一个包送入原 Motion 移动回调一次，再只交给
菜单的点按识别；普通 Gesture 点击/拖动回调被明确 withhold。菜单的
`IModeMenuCursor` 只捕获打开锚点并读取实际系统位置，不调用 SetCursorPos、不写
光标、不积累私有位置；已删除菜单专用 `TouchSessionProcessor` 位移累积与补偿。
高亮由 ModeSession 维护循环 `Refresh` 持续读取实际位置更新，点按在 `Click` 中再次
读取；请求目标、预测位置或另一私有操作指针都不参与选择。
整个选择接触，包括中心/菜单外点击，都由菜单消耗；普通 GestureProcessor 不接收
这些包。普通 Motion/HID 移动、正式灵敏度与量化继续生效，不调用普通鼠标键输出。

进入时同步调用既有 Motion.Reset、Gesture.Reset、CancelPendingAndRelease，终止
重建、C release/glide、旧拖动和待点击，确保开始菜单后的旧工作不再输出。进入前
已保持的鼠标左键会正常释放，并以独立的 `left_button_safety_release:
reason=menu_enter` 记录保存，不与菜单点按的 `mode_output` 记录混同。
B/X GamepadSessionProcessor 立即清除 dwell 并 Neutral；菜单期间只消耗有序状态，
不输出。保留接触序号水位。关闭后，若最后仍是旧非 Neutral 状态，须观察 Neutral
后才能接纳新状态，旧刷新不能复活。新 Sender run 清除旧屏障，旧 run 仍由既有规则
拒绝。没有改变正常 B/X 手势、阈值、映射、反馈、dwell 或设备。

退出时重置菜单接触和正常输入链，释放在途动作、撤销队列。普通鼠标只从下一次
明确 DOWN 恢复；旧 MOVE/UP 和旧点击资格不进入游戏，不补发菜单期间位移，不恢复
旧拖动。菜单接触、配置、输出队列与释放维护同属 ModeSession 的锁和生命周期，
不使用跨代次异步动作回调，也不持有输入锁等待 UI。

## 当前代码位置

- `windows/Rightpad.Receiver/WindowsModeMenuCursor.cs`：`GetCursorPos` 读取真实
  系统位置；`MonitorFromPoint`/`GetMonitorInfo`/`GetDpiForMonitor` 固定打开锚点的
  监视器与 DPI；只读，无光标写入或可见性/约束读取。`IModeMenuCursorApi` 只有
  `Position` 与 `Area`，诊断字段为 `actual`/`display`/`win32`。
- `windows/Rightpad.Receiver/ModeMenu.cs`：`Click` 重新读取最终系统位置；中央
  返回 -1；已绑定槽位调用 `execute(key, ClickFeedback)`，未绑定槽位调用未绑定
  完成回调并携带同一合格 UP 的 `ClickFeedback`。
- `windows/Rightpad.Receiver/ModeSession.cs`：`Pulse`/`CompleteMenuAction` 处理
  已绑定按下、释放、确认与关闭；`UnboundTap` 处理未绑定一次确认后立即关闭；
  `CloseMenu` 设置 `freshTouch=true` 并经 `MenuBoundary` 清理 Motion/Gesture。

## 外观、焦点与显示

WPF 原生浮层继续使用 Receiver 技术栈，不新增浏览器、应用或插件框架。
菜单固定为六个完整宽扇区和中央中性圆，不再渲染独立按钮，也不提供外观切换
控件；设置窗口只保留一个不可点击的环形预览。名称为主信息，
键盘/手柄点按为辅信息；悬停/点击颜色区分。扇区底色不透明，外围透明，不遮暗游戏。
固定外观共享方向选择及 MenuPlacement；默认直径 480 DIP，小显示区整体缩放。
12 DIP 选择阈值不随装饰直径缩小；中央小圆轮廓标明固定中性边界，外围大圆用于说明。

打开通过 `GetCursorPos` 读取当前 OS cursor 的物理屏幕位置，并读取监视器完整屏幕
区域和 DPI。
真实光标位置＝固定选择锚点＝视觉中心；打开不调用移动 API，不夹取中心。
靠边/角落时装饰被屏幕裁切，固定说明条夹在屏幕内，始终显示选中方向/绑定或中性。
系统屏幕边界限制向屏幕外移动，因此靠边打开时朝外方向可能不可达；可用 Mode 关闭，
在普通输入下移向屏幕内再打开。不移动光标、不平移锚点来隐藏这一限制。支持负屏幕
坐标；主程序声明 PerMonitorV2。浮层设置 Topmost、NOACTIVATE、TOOLWINDOW、TRANSPARENT，
不接收 Windows 鼠标输入、不主动抢前台。

**真实位置可见标记（2026-10-22 本轮）**：菜单打开时，无论系统光标本身是否可见，
同一浮层都在最后绘制一个白色主体、黑色外轮廓的小箭头（20×27 DIP）。外轮廓尖端
精确位于同一 `ModeMenuSnapshot.CursorX/CursorY`；复用 Ring 的屏幕物理坐标变换，
先扣监视器原点，再按现有浮层比例转换，箭头几何按 `Placement.Area.Scale` 缩放，
支持非零/负坐标与 DPI。箭头不随小显示区的 Ring 装饰缩小。标记仅显示已观测位置，
不另读光标、不积累位移、不平滑/预测/延迟/补偿，也不夹到环形或屏幕边缘；超出当前
Overlay 区域自然裁切。箭头位于扇区、中性圆和说明条之上，保留高亮与选中项文字。
真实 Windows 光标仍是高亮、点按与方向选择的唯一依据，标记不是另一套操作指针。
菜单关闭、故障退出、Stop 或 Presenter Dispose 时，箭头随原浮层隐藏/关闭。

[软件绘制候选交付](MODE_MENU_CURSOR_SOFTWARE_DELIVERY_20261022.md)和

光标隐藏/受抑制（`CURSOR_SHOWING` 为 0）不再视为坐标不可用，`ClipCursor`
小于打开监视器也不再视为失败；两者都不读取、不比较、不解除，也绝不调用
SetCursorPos/ShowCursor/ClipCursor/SetCapture。真实 `GetCursorPos`、
`GetMonitorInfo`、`GetDpiForMonitor` 读取失败，或打开锚点的监视器区域/DPI

异常日志记录刷新/点按/维护阶段、类型、消息、实际坐标、打开及当前显示区域/DPI

仍保留设备错误门闩。
菜单仅显示于本次打开选择的监视器；重新打开才重新取位置和显示区。

普通桌面浮层不保证独占全屏游戏可见，不使用进程注入、游戏 Hook 或隐藏 fallback。
菜单移动现在提交真实 HID 相对移动，因此游戏可以收到该移动；同时菜单点按不产生
普通鼠标左键或拖动。没有全局 Hook、游戏注入或系统级持续约束，因此不宣称所有

## 配置兼容与安全边界

`modeControl` 原 `kind/key/behavior` 保留，并增加以下可选字段：

```json
"purpose": 0,
"appearance": 0,
"slots": {
  "top": {"kind":0,"key":""},
  "upperRight": {"kind":0,"key":""},
  "lowerRight": {"kind":0,"key":""},
  "bottom": {"kind":0,"key":""},
  "lowerLeft": {"kind":0,"key":""},
  "upperLeft": {"kind":0,"key":""}
}
```

`purpose` 0=原单键、1=菜单；`appearance` 固定为 0=完整环形。旧文件中的
`appearance: 1` 只在读取时把外观字段规范化为 0，保留 `purpose`、`kind`、`key`、
`behavior`、六个槽位及其他全部设置，不触发整个 `modeControl` 的默认回退；加载
不写盘，显式 Save 才写回 0。槽位 kind/key 复用原目录规则。缺少新字段时保留原绑定、
行为并选择单键；新槽位全部未绑定。非法完整 Mode 记录仍按既有设置错误规则回退，
并保留其他设置。两用途各自配置同时保留，切换用途不覆盖原单键。

配置完整值相等时不操作输出；实际变化释放、关闭、清空本次菜单动作并更换 RPMD
代次，不将当前接触按新配置解释。普通 UP 不等于断线；Mode UP 的既有刷新继续维持
菜单租约。CANCEL、Mode 600 ms lease、presence/源/新 run、安全输入模态、Stop、
Safe Restart、Dispose、显示/导航/输出异常关闭菜单并恢复新接触路径。原维护循环
还检查固定 2 s 呈现健康期限：界面持续不响应时主动退出菜单，不依赖 UI 回调才能
恢复正常输入。输出失败使用原独立设备清理与错误门闩，不停止正常鼠标路径。
