# rightpad：我的操作方式、开发习惯与项目成果

整理日期：2026-10-17  
适用项目：`C:\rightpad`  
文档用途：个人使用说明、开发协作约定和新聊天交接背景。  
依据：对话中的明确要求、当前 `AGENTS.md`、架构和功能交付文档，以及整理时的只读 Git 查询。

这份文档把长期使用条件、协作习惯、已交付成果、验证边界和讨论中的想法分别记录。它不构成对部署、清理、提交或推送的额外授权。具体任务以我最新的明确指令为准，项目技术细节仍需阅读当前 `AGENTS.md` 和相关设计文档。

**当前交接重点：Mode 已经从空白区域变成可配置单键按钮，支持键盘／手柄绑定和普通按钮／切换按住；远程布局编辑、大预览和 B3 修复也已有交付。用户已确认源码推送成功。**

本次整理只读取资料和 Git 元数据、更新本文，没有重新构建、测试、部署或操作设备。下文的测试数量、PID 和运行状态均注明其来源，不能作为未来某一时刻的实时检查结果。

## 1. 我的实际操作条件

- 我的左手不能使用，目前单手操作手机。
- 我只用一个手指操作 rightpad，手指能够舒适移动的范围很小。
- 我没有实体鼠标和键盘。
- **rightpad 是我控制电脑的唯一设备。**
- 手机保持竖屏，作为专用触控表面使用。
- 使用过程中，我通常看电脑，不看手机屏幕。
- 直接操作手机设置比较困难，因此希望重要配置尽量在 Windows Receiver 中完成。

设计和开发时，必须把这些条件作为真实使用前提。不能假设我能换一只手、增加一根手指、拿起其他输入设备，或者在手机上完成复杂操作。

## 2. 我的主要使用场景

rightpad 最主要的用途是打游戏。我平时主要通过 Steam 玩游戏，玩的多款游戏支持手柄。

当前使用方式包含触控板鼠标输入和手柄按键输入。我关心单指条件下的游戏操作效率、视角手感、可靠性，以及长时间使用是否方便。

游戏中的手柄／键鼠提示图标来回切换，是我已经提出的问题。讨论这个问题不代表我已经同意把整个项目改成纯键鼠或纯手柄输出，具体方案需要另行确定。

## 3. 我希望怎样使用界面

### 3.1 Receiver 是主要配置入口

- 尽量让我在电脑上选择、调整和保存配置。
- 优先提供大按钮、清晰的选中状态和明确的当前值。
- 常用配置应能只通过鼠标左键点击完成。
- 不要把实体键盘录入、快捷键、右键或滚轮作为完成配置的必要条件。
- 选择按键时，应提供可点击的选择器，不能要求我按实体键盘或手柄录入，也不能要求我填写扫描码等内部数值。
- 不能把普通使用流程依赖在手工编辑配置文件或运行命令上。

### 3.2 手机上的操作应适合单指盲操作

- 常用区域要容易触及，尽量减少跨区域的大幅移动。
- 区域的位置、大小和操作含义应明确、稳定。
- 不设计需要同时按住两个区域才能工作的必要操作。
- 不新增未经我要求的多指手势、陀螺仪或加速度计操作。
- 新功能应围绕我的实际操作限制设计，而不是直接照搬普通双手手柄或多指触控板。

### 3.3 布局预览需要大而完整

我希望直接看清整部手机的布局和各区域比例。

已经明确表达的偏好包括：

- 预览中的鼠标区域使用纯黑色，避免与蓝灰色界面背景混在一起。
- 充分利用窗口空间展示完整的竖屏布局，保持正确比例。
- 参数和操作按钮仍然要方便点击，不能为了放大预览而把配置控件缩得很小。
- 独立的大布局编辑窗口，是已经接受过的界面方向。
- **不需要 1.5 倍／2 倍放大，也不需要顶部／中部／底部定位。**我需要的是清楚的整体布局，不是局部细节查看工具。

## 4. 布局修改的生效规则

这是我明确要求的交互约束：

1. 在 Receiver 编辑位置、宽度和高度时，只修改电脑草稿。
2. **编辑过程中，手机布局不能实时生效。**
3. 只有我明确点击“试用布局”，手机才应用候选布局。
4. 试用期间，我可以点击“保留此布局”确认保存。
5. 倒计时结束前，如果我没有确认保留，就撤销本次编辑，恢复试用前的原布局。

当前已经讨论并交付过的布局流程使用 60 秒试用。恢复目标是本次试用前的正式布局，不能擅自变成出厂布局、历史测试矩形或另一台电脑的旧草稿。

试用安全不能依赖 Receiver 一直在线。网络中断、电脑端退出等情况，也不能让不合适的候选布局永久留在手机上。

这些是布局编辑的明确要求。其他设置如何生效，应按该设置已经确认的规则处理，不要把布局试用机制未经讨论扩展成所有设置的统一机制。

## 5. 开发期间，我最重要的要求：恢复实际控制能力

**开发过程中可以暂时失去触控板连接，但是任务完成或失败后，都必须恢复连接和实际操作能力。**

对执行开发任务的 Codex，具体含义是：

- 在停止 Receiver、替换文件、更新 Android 或进行可能影响输入的操作前，先准备可用的备份与恢复办法。
- 恢复不能依赖我在失去输入以后手动点击、输入命令或使用另一台输入设备。
- 恢复保护需要能在待更新程序不可用时继续发挥作用。
- 使用项目当前认可的启动、部署和恢复流程，避免运行程序随开发工具退出而一起被终止。
- 失败时应恢复到已知可用状态，并报告失败原因与仍未完成的工作。
- 结束时要检查实际鼠标移动、单击和现有正常拖动，以及与本次改动有关的按键释放状态。
- “进程存在”“显示 Connected”“编译成功”都不足以单独证明我已经恢复控制。

对于无法完成的恢复，应如实报告具体状态和阻碍，不能把失去控制的状态标记为完成。

需要补充信息时，尽量集中在真正影响方案的少量问题上。执行阶段对已经明确授权的常规步骤，应继续完成；真正越过范围或遇到外部阻碍时，说明原因。

## 7. 我希望开发提示词包含什么

一份可以交给执行 Codex 的提示词，应该明确：

1. **目标：**这次具体解决什么问题，完成后我能怎样使用。
2. **使用条件：**单指、小范围、手机竖屏、通常不看手机、没有其他输入设备。
3. **范围：**实现哪些功能，哪些建议留到以后。
4. **交互：**按下、移动、抬起、取消、保存、断线时分别发生什么。
5. **配置：**在哪里选择、何时生效、失败时保留什么状态。
6. **保护：**保留现有设置、布局和已接受的输入行为。
7. **验证：**需要哪些自动化、真实输出和界面检查，怎样判断成功。
8. **部署与恢复：**如何部署、如何回退、结束时如何证明我已恢复控制。
9. **交付：**改了什么、测试结果、运行版本、恢复路径与验证边界。
10. **Git：**明确本轮是否包含 commit、push；不从历史授权推导本轮授权。

提示词应让执行者可以开展工作，避免仅有抽象建议，也避免加入与当前需求无关的架构和功能。

## 9. 与使用偏好直接相关的项目技术原则

以下内容来自项目现有约束，供理解我的产品方向；详细规则和已批准的实验例外应查阅当前 `AGENTS.md`。

- 游戏手感、游戏兼容性、稳定可靠，是重要目标。
- 视角运动需要平滑、稳定、可预测，兼顾微调和长期舒适度；不只追求最低延迟数字。
- 正常鼠标路径采用相对位移语义，不能擅自改成摇杆速度控制。
- 手感参数应固定、可复现，不根据手指速度、网络、帧率或游戏自动调整。
- 已明确批准的模式和实验例外应准确保留，不能用概括性规则误删。
- 新按钮功能不构成修改现有 Motion 算法或已接受参数的授权。
- 采用有实际收益的必要复杂度；代码少、成本低本身不是唯一目标。
- 项目已有明确的架构与平台范围，不能为了方便功能无故扩大为云服务、账号系统或其他平台产品。

## 10. 目前已经交付的主要成果

本节依据当前架构、功能说明及交付报告整理，不把报告中的历史描述和旧基线混为当前契约。

### 10.1 基础输入系统与运动控制

- Android 到 Windows 11 的专用游戏输入链路已建立，手机提供单指触控采集，Receiver 负责鼠标运动、鼠标手势、配置和 Windows 输出。
- 已有相对鼠标移动、单击和双击拖动。后续布局和 Mode 部署也保留了真实移动、单击、拖动的功能验证记录。
- 正常鼠标后端为 libvirtualhid Virtual HID Mouse；SendInput 只作为明确选择的开发诊断路径，不是生产自动降级。
- 已有局域网发现、连接状态及 Sender 重启后在原 Receiver 上恢复的机制，避免用户手工填写固定电脑 IP。
- Android 在前台防止自动熄屏，离开前台后释放该前台保亮行为。
- 正常启动使用 M-R1。其主要路径为固定 M8 重建、直接重建位置、Q0-C 量化、1 ms 输出机会及重建完成释放，不使用鼠标滑行。
- Receiver 本地可以选择 M-R1／C-Z1，选择、待生效和实际活动状态分开处理；这与现在的 Mode 按键绑定是不同功能。
- C-Z1 有 Receiver 参数面板，按已有安全边界应用完整固定参数快照。C-Z1 的 true glide 是已经明确批准的例外，不能扩大为正常鼠标路径的普遍权限。
- 保存的实际个人参数应保留。文档中的默认值、历史实验值和当前用户值不能互相替代。

上述内容不构成“所有游戏兼容”“客观延迟优于其他方案”或“硬件轮询率更高”的证明。

### 10.2 已接受的 B／X 游戏控件

| 区域 | 已有操作含义 |
|---|---|
| B | 基础／轻点／长按为 B，向上滑为 Y，向下滑为 A |
| X | 基础为 X，向左／向右／向上滑为对应方向键 |

这两个控件复用同一个 Xbox360 输出设备，按各自稳定 ID 合并贡献。已有 Receiver 行为配置、保存后同步、按下时取配置快照及独立手机布局存储。

既有 B、X 和触控板反馈有各自已经接受的规则；Mode 的无触觉反馈要求不改变它们。当前架构文档记录，B／X 相关阶段在 2026-09-20 已取得真人设备验收；后续新增功能不能直接继承这项验收。

### 10.3 电脑远程布局编辑与大预览

已经实现并部署：

- 在 Receiver 选择 B、X、Mode，使用大号加减按钮和 1／10／50 px 步长调整 X、Y、宽度、高度。
- 手机保存唯一正式布局；Windows 编辑草稿，先读取手机实际布局，不用旧电脑缓存覆盖手机。
- 只有明确点击“试用布局”才应用候选；手机以本地单调时钟管理 60 秒试用。
- “保留此布局”由手机成功保存后确认；超时未保留恢复本次试用前布局。
- 已有版本、几何、重复消息、结果查询和迟到事务处理，保存与超时竞争有回归覆盖。
- 已有默认最大化的独立大编辑窗口，保留“返回 Receiver”，展示完整、等比例的手机预览。
- 预览采用纯黑鼠标区域、绿色控件、白色选中框、橙色固定工具；没有加入我明确不需要的局部放大和定位功能。
- 当前大布局编辑器的外观已经得到我的接受。

既有布局交付记录包含真实试用、保留、超时恢复、立即恢复和用户原始文件还原等证据；后续不同阶段有各自的验证范围，不能把某一阶段没测的项目自动说成该阶段已通过。

### 10.4 B3：旧布局试用请求迟到生效的修复

B3 原问题是：未确认的首次 Try 在编辑器隐藏后被保留，过很久重新打开仍可能重发，造成旧编辑意外开始试用。

已经修复并部署：

- Receiver 未确认操作具有固定 3 秒总寿命，过期后不能通过强制轮询继续重发。
- 隐藏、关闭、最小化等接点先转换到结果核对状态，再停止计时器。
- 重开编辑器核对手机实际结果，不重放旧 Try。
- 未得到权威结果时显示待确认并限制新试用，不猜测已经恢复或封存。
- C# 客户端、真实 WPF 生命周期接点与 Java 布局事务类之间有针对性回归。

**这里的 3 秒是未确认请求的寿命，手机布局试用仍为原来的 60 秒。**

该修复已有独立提交。历史审计中的其他条目不能因为 B3 完成，就被描述为也已经修复；其现状需要按新的实际任务另行核实。

### 10.5 Mode 单键绑定：已实现、部署并进入已推送源码

Mode 已经不再是空白／无操作区域。当前功能复用 `rightpad.input.mode` stable ID 和原手机矩形，在 Receiver 管理一个键盘或手柄绑定。

实际入口与操作步骤：

1. 打开 **Receiver → Controls → Mode · 单键绑定**。
2. 点击选择键盘键或手柄键，通过分类大按钮选择。
3. 选择“普通按钮”或“切换按住”。
4. 点击选择器里的“完成选择 · 返回统一 Save”。
5. 点击主窗口底部统一的 **Save**，成功写盘后生效。

选择器没有独立保存入口。选择键位和行为期间只修改草稿，不提前影响正式绑定。

| 行为 | 当前实现的含义 |
|---|---|
| 普通按钮 | 新的有效 DOWN 按下，持续接触保持，正常 UP 请求释放；极短接触完成固定的 25 ms 最小可见时间后释放，安全释放绕过该时间 |
| 切换按住 | 每次新的有效 DOWN 切换一次；正常 UP 保持当前状态，下一次新的 DOWN 释放；重复或迟到消息不能反复翻转 |

长按键盘键可能产生 Windows 自身的常规键盘重复；rightpad 没有为此增加主动连点定时器。正常按钮的最小可见时间也不等于长按识别等待。

#### 实际支持范围

- **117 个键盘目录项：**常规 104 键范围，加 F13–F24 和 ISO 额外符号键；左右修饰键、主 Enter／数字小键盘 Enter 等分别编码。
- **16 个手柄绑定：**A／B／X／Y、LB／RB、View／Back、Menu／Start、方向四键、左右摇杆按下、LT／RT。
- LT／RT 为二态，按下 255、释放 0；不是本轮新增的模拟幅度调节。
- 当前不提供 Fn、厂商专用硬件键、媒体／消费控制键、鼠标键或 Guide。Guide 的边界是本轮没有完成其 Windows／游戏行为验证，不能据此声称原生层完全无法编码。
- 符号标签代表物理键，实际字符仍受 Windows 键盘布局、修饰键及锁定状态影响，不自动组合 Shift。

#### 已有可靠性与输出机制

- Receiver 是绑定和保持状态的权威端，Android 通过独立 type8／RPMD 上报接触事实，复用现有端口与工作线程。
- 有界转换队列、确认重传、固定租约和生命周期代次处理重复、丢失、乱序和旧接触失效。
- 改绑或更换行为先释放旧输出，新配置等待下一次新接触；相同配置和无关 Save 不重复动作。
- 正常 UP 后的切换保持可以与后续鼠标、B／X 操作并存；安全中断清除，重连或重启后不自动保持。
- 原生桥增量加入 driver-backed keyboard extension v1，保留 mouse／gamepad ABI2，未升级系统驱动、Broker 或许可组件。
- 键盘使用独立 HID 键盘设备；手柄复用原单个 Xbox360。Mode 只撤销自己的贡献，不误清其他控件。
- **没有新增 Mode 触觉反馈，Mode 接触也不输出鼠标 Touch。**
- 原有 Motion、灵敏度及 B／X 已接受手势、参数、反馈保持原样。

#### 交付配置和界面说明

交付时已将临时测试绑定清除，正式保存为“未绑定 · 普通按钮”。这只是交付时的状态；我之后可能已经改绑，后续任务应读取当前正式设置，不能强制恢复成未绑定。

手机目前保留既有外观和静态 **M** 标签。它不代表当前绑定键，也不代表 M／C 选择。**绑定、行为和实际保持状态以 Receiver 显示为准。**
