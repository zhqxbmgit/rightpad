## 1. 接手时先记住的十条约定

1. 我左手不能用，没有实体鼠标和键盘，只用一个手指在竖屏手机很小的范围内操作。
2. 我通常看电脑、不看手机；rightpad 主要用于游戏，尤其是支持手柄的 Steam 游戏。
3. 重要设置尽量放在 Receiver，用大按钮和左键完成，不依赖实体按键录入、右键、滚轮或手工命令。
4. 我说“先讨论／不要执行”时，只讨论；我说“写提示词”时，只交付提示词，不能自行实施。
5. 已获授权的常规工作应主动完成；遇到确实缺少的授权、必要信息或工具能力时，明确说明。
6. 保护当前正式设置、手机布局、已接受手感、已有未提交修改及有价值的证据。
7. 影响唯一输入通道前，先建立可用的独立恢复保障；结束时验证真实移动、单击、拖动及释放状态。
8. 区分计划、源码实现、构建、回归、部署、生产输入验证和真人游戏验收，不能互相替代。
9. Git commit、push、历史修改和清理按本轮明确授权处理，不沿用旧任务授权。
10. 当前菜单只保留 Ring。“移动走原 Motion/HID、点按由菜单独占”已实现、部署并完成生产链路自动化验证；允许游戏收到菜单导航位移，菜单点按不生成普通鼠标左键。真人盲操作与真实游戏体验仍待验收。

## 2. 我的真实操作条件及其设计含义

### 2.1 操作方式

- 我的左手不能使用；不要把双手协作当成设计前提。
- 只用一个手指，舒适移动范围很小。
- 手机竖屏，作为专用输入表面。
- 使用时主要看电脑，不能假设我会盯着手机找按钮或读提示。
- 没有另一套实体鼠标、键盘或手柄供故障时接管。
- rightpad 既是游戏输入设备，也是我实际控制这台电脑的唯一通道。

这些是设计的基础条件。不能通过“换一根手指”“同时按另一个区域”“拿键盘输入一下”解决可用性或恢复问题。

### 2.2 单指游戏需求

我主要玩支持手柄的 Steam 游戏。关心的体验包括：

- 用很小的手指移动稳定控制视角。
- 单指条件下完成移动、视角与常用动作的切换。
- 微调可控，长时间使用舒适，动作含义稳定。
- 尽量从电脑完成游戏相关配置。
- 避免误触、额外操作步骤、输入卡住和突然改变手感。

“一边前进一边移动视角”是我提出的重要使用需求。具体功能方案仍需按任务确认，不能因此擅自加入新的摇杆、保持机制、宏或控制模式。

### 2.3 界面必须适合左键点击

常用操作应提供大按钮、明显选中状态、清楚的正式值和运行状态。

- 绑定选择使用可点击目录，不能要求按实体键盘／手柄录入。
- 不要求输入扫描码、虚拟键码、内部枚举或手改 JSON。
- 不把右键、滚轮、快捷键、按 Enter 作为完成配置的必要条件。
- 必要提问和提交操作也应能通过大按钮、左键完成。
- 手机控件的位置、大小和含义应稳定，优先减少跨区域的大幅移动。
- 不新增未经要求的多指手势、陀螺仪、加速度计或同时按住多个区域的必要操作。

重要配置由 Windows Receiver 承担；Android 的鼠标路径主要负责采集与传输原始触摸事实。已经批准的 B/X 局部手势识别属于明确例外。

## 4. 配置、手机布局和保存语义

### 4.1 行为设置

- 绑定、行为、灵敏度等设置以 Receiver 的现有配置流程为准。
- 草稿和正式值必须分开，不能在选择过程中偷偷生效。
- 采用当前已经确认的统一、磁盘优先 Save；写盘成功后再发布正式值。
- 保存失败时保留原正式配置，明确显示错误和未应用的草稿。
- 保留与任务无关的设置、未知属性和已有个人参数。

不能用文档默认值、旧交付配置或测试夹具覆盖当前用户设置。“交付时未绑定”不代表以后始终未绑定。

### 4.2 布局编辑

我需要的是完整、清晰、等比例的竖屏整机布局预览：

- 鼠标区域纯黑，便于和其他界面区分。
- 尽量利用电脑窗口空间，保留容易点击的参数控件。
- 已接受独立的大布局编辑窗口。
- 不需要额外的 1.5 倍／2 倍局部放大，以及顶部／中部／底部定位功能。

布局的生效流程有独立规则：

1. Receiver 编辑位置和大小时只修改电脑草稿，手机不能实时跟着变。
2. 明确点击“试用布局”后，手机才应用候选。
3. 手机负责 60 秒试用期限；用户明确保留后才成为正式布局。
4. 未保留则恢复本次试用前的正式布局。
5. Receiver 退出或网络中断，不能使候选布局永久留在手机上。
6. 恢复源是该次操作前的现场正式文件，不是出厂布局、旧报告或历史测试矩形。

B3 修复中 3 秒是未确认请求的总寿命，不是把手机试用期从 60 秒改成 3 秒。不要把布局试用机制未经讨论推广到所有设置。

### 4.3 临时测试配置

与本轮任务有关、且已有授权的临时配置，应做到：

- 操作前持久备份现场正式值和必要的原始文件。
- 使用安全绑定、观察目标和有界输入。
- 测试完成后恢复该轮开始时的值。
- 同时核对磁盘文件与运行时生效值；不能只改回文件，让临时绑定继续生效。
- 如声称字节一致，提供实际字节或哈希核对。
- 暂时更改配置的时间窗口、失败尝试和恢复结果要如实记录。

缺少必要测试授权时，直接指出缺项；不能一边跳过必需验收，一边宣称全部完成。

## 5. 唯一输入设备的恢复要求

### 5.1 恢复必须在断开前准备

开发允许必要的短暂断开。停止 Receiver、替换正式文件、更新 Android 或改变重要配置前，应按任务风险准备：

- 当前运行程序及依赖的可用备份。
- 现场设置和涉及的手机布局备份。
- 经核对的恢复路径、脚本执行环境和必要依赖。
- 能独立于将被停止的程序、当前终端和 agent 会话继续工作的保护。

“已经写了恢复脚本”“计划任务注册成功”不等于保护有效。需要在真实独立启动环境中验证脚本能启动、找到正确备份并完成预检，再进入需要保护的操作窗口。

### 5.2 区分恢复证据的强度

| 实际做过的检查 | 可以证明什么 |
|---|---|
| 脚本语法、路径、依赖及备份哈希检查 | 预检满足相应条件 |
| 独立计划任务运行预检成功 | 该环境能启动并完成预检 |
| 替换健康接口，预演“不健康”决策 | 决策分支符合设计 |
| 部署后发现新进程健康，直接退出 | 部署后的健康放行分支可用 |
| 真正替换回备份、独立启动、恢复输入 | 对应场景的实际恢复成功 |

不能把后一轮健康检查当作前一轮部署窗口已经受保护的证明。

不要求为了补证据故意破坏唯一输入通道。未执行真实恢复分支可以如实保留为限制，不能写成已经验证。

### 5.3 结束时恢复“实际可操作”

完成或失败后，按本次修改范围检查：

- 普通鼠标移动。
- 真实单击。
- 正常双击拖动并在抬手后释放。
- 涉及的键盘键、修饰键、鼠标键、手柄按钮／扳机／摇杆无残留保持。
- 正式设置与运行时一致，临时绑定和测试布局已经撤销。
- 临时观察器、后台任务和恢复保护在适当时机正常收尾。

进程存在、Connected、窗口响应、零输出失败或构建通过，都不能单独证明我已恢复实际控制。

如果恢复未完成，应明确说明当前还能怎样操作、具体阻碍和剩余工作，不把任务标记为完成。

## 6. 构建、部署与运行版本的工程约束

这些是当前项目规则的摘要；细节以[AGENTS.md](/C:/rightpad/AGENTS.md)和相应任务的明确阶段限制为准。

### 6.1 Windows Receiver

影响 Receiver 实际运行行为的修改，通常需要完成：

1. 适用构建和测试，优先隔离输出，避免正式 EXE 锁定或半成品污染运行目录。
2. 保护就绪后停止旧 Receiver，确认进程退出、UDP 50000 释放。
3. 通过项目批准的独立启动器启动新版本。
4. 核对实际加载版本、DLL 哈希、进程、当前用户、与 explorer 相同的交互 Session、Medium 权限及 Default 桌面。
5. 核对监听归属、Android 自然重连和本次所需端到端操作。
6. 恢复设置与控制后再完成收尾。

当前批准的独立启动器是[RightpadReceiverTask.ps1](/C:/rightpad/windows/tools/RightpadReceiverTask.ps1)。持久 Receiver 不应作为 agent 执行 shell 的长期子进程，避免继承工具宿主的终止生命周期。

apphost EXE 可能不随 C# 修改改变，不能只看 EXE 哈希便判断部署了新代码。进程 PID 也必须结合创建时间、路径与版本核对。

任务明确限定为只讨论、只读分析、文档、隔离构建或禁止部署时，应遵守该范围；不能用一般部署规则扩大授权。文档修改不需要重启 Receiver。

### 6.2 Android

不因 Windows 修改顺便更新或重启 Android。若任务涉及 Android 构建、部署，应遵守当前项目规定，完成适用的安装、前台启动、新 Sender 接纳和端到端恢复。

Windows Receiver 应能接纳重启后的 Android Sender，而不依赖重启 Windows。两个端的生命周期应分别处理。

Android 前台防止自动熄屏，离开前台后解除；不未经批准引入 WakeLock 或后台服务。

### 6.3 工具与后台任务

- 关键脚本按实际使用的 PowerShell 版本验证，不假定当前交互 Shell 与计划任务环境相同。
- 同一运行目录、正式配置和 Receiver 生命周期的修改应协调，避免多个执行过程同时操作。
- 接手前一代理的产物时重新核对现场，不沿用旧 PID、旧锁或旧候选假设。
- 任务超时、取消或换会话后，明确必要子进程、观察器和保护任务是否仍在运行。

## 7. 游戏手感和架构约束

### 7.1 产品目标

rightpad 是 Android 到 Windows 11 的专用游戏输入系统。主要目标是游戏手感、兼容性、稳定可靠、延迟与抖动、输入一致性和单指可用性。

视角需要平滑、稳定、少摆动、自然连续，同时保持微调、转向、停止和长时间使用的舒适度。项目不是只按最低延迟数字排名；固定、可测、可预测的响应代价，可以在实际收益和真人游戏证据支持下讨论。

不因代码量、开发难度或价格直接否定有明确收益的方案，也不因为驱动、付费组件或复杂算法“看起来高级”就采用。金钱成本与供应商、许可、离线可用、驱动维护、部署和恢复依赖要分别评估。

### 7.2 Relative Mouse 与固定手感

- 普通鼠标保持相对位移语义，不擅自改成摇杆速度控制。
- 不增加基于速度、噪声、网络、FPS、游戏或负载的动态灵敏度、增益、平滑、延迟或自动模式切换。
- 不增加未经批准的预测、人工惯性、自动居中或新滑行。
- 固定滤波完成已经获得的真实位移，与继续制造额外距离的惯性不同。
- 已经批准的明确例外应保留，不能用一句概括规则误删。

正常启动选 M-R1；C-Z1 是明确批准的独立选择。M-R1 使用固定 M8 重建、直接重建位置、Q0-C、1 ms 输出机会和重建完成释放，无 glide。保存的 Tau/Support 不参与 M-R1 位置整形；正式灵敏度按已有规则生效。

C-Z1 的固定 true glide 是批准例外。其默认、历史实验与用户当前保存参数必须分开，不能借“恢复 Z1”覆盖现场个人值。

按钮、布局或菜单任务不自动授权修改 Motion。参考实现只提供设计证据，不是 rightpad 必须照搬的目标或参数表。

### 7.3 输出与平台

- 生产鼠标后端是 libvirtualhid Virtual HID Mouse。
- SendInput 仅为明确指定的开发／诊断覆盖，不是生产自动降级。
- 虚拟 HID 初始化失败应保留可见错误，不静默换后端。
- 键盘扩展、mouse/gamepad ABI 和既有单个 Xbox360 输出设备按当前契约保留。
- Android 负责鼠标触摸采集、历史样本、时间戳和传输；Receiver 负责 Motion、鼠标手势、配置和输出。
- 不无故扩展到其他平台、远程桌面、串流、账号、云同步、自动游戏识别或一般插件框架。

rightpad 是可信局域网内的个人设备系统。按当前架构，不主动加入认证、配对、PIN、加密、证书、HMAC、来源锁等体系；报文格式校验、超时和防卡住等可靠性措施仍需要。

### 7.4 B/X 与 Mode

- B/X 已接受的映射、手势阈值、反馈和个人参数保持，不为菜单任务顺便调整。
- B 基础操作为 B，上滑 Y，下滑 A；X 基础为 X，左／右／上滑为相应方向键。
- Mode 原单键用途保留键盘／手柄绑定、普通按钮和切换按住。
- Mode 不新增触觉反馈；不因此取消 B/X 或普通触控板已有反馈。
- 手机静态 M 标签不代表实际绑定，也不代表 Receiver 的 M/C 选择。
- Mode 绑定、用途和保持状态看 Receiver；Receiver 本地 M/C 与 Mode 按键独立。

### 8.3 已交付：移动复用原路径，点按留给菜单

我实测 leftpad 菜单打开后移动鼠标，游戏会收到位移。我明确表示这项代价对我无关紧要；关键是选菜单的手机点按不能向游戏发出普通鼠标单击。

因此，已经确认并交付的行为是：

- 菜单打开时，移动复用原来的 Motion → Virtual HID 路径。
- 允许游戏收到这些导航位移。
- 不再用菜单专用 SetCursorPos 输出制造另一套移动响应。
- 菜单仍读取实际系统光标选择方向。
- 菜单点按在普通鼠标单击／双击拖动生成前分流，只执行槽位绑定。
- 保留进入、退出、断线、错误时对旧拖动、待点击和旧接触的清理。
- 不增加系统 Hook，不采用先发送鼠标单击再尝试拦截的方式。

**状态：2026-10-20 已收到交付报告，并只读核对关键路由、构建／测试记录、生产输入证据、运行版本及正式设置。** 当前 AGENTS、架构和菜单契约已同步移动路径例外；旧绝对定位与全量导航隔离的报告保留为历史，不再代表当前移动路由。

该轮隔离 Release 构建记录为 0 警告／0 错误，Windows 回归 765/765。相同手机位移 (20,10)，菜单关闭、菜单打开、关闭后三段均得到 HID／Raw Input 240,120、系统光标 480,240；在该实测条件下，原菜单速度差异已经消除。菜单上槽 A 点按观察到键盘按下／释放各一次，同一窗口 HID 鼠标左键事件与目标窗口左键按下均为 0，菜单保持打开；普通单击和双击拖动恢复有记录。

以上是 2026-10-20 现有 Android 实例经 ADB 单指注入的历史生产链路验证，不是物理手指、真人盲操作或真实游戏验收。其中“菜单保持打开”和隐藏/约束退出策略已被 2026-10-21/22 当前规则取代；本轮不重跑手机注入或游戏测试。详见[移动／点按分流交付报告](/C:/rightpad/docs/MODE_MOTION_ROUTE_DELIVERY_20261020.md)。

### 9.3 控制证据体积
