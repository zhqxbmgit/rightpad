# 小米 14 正式版触控报点稳定性复测（2026-11-04）

## 结论

本轮验证了约 238 Hz 的主要位置更新节奏在两轮较长单指接触中可重复出现，前台保持后复测没有发现持续切换为约 120 Hz 的逐秒中位数段落。但完整间隔存在明显长尾，未证明严格等间隔、无间断 240 Hz，也未完成长时连续操作或热稳定性验收。

设备仍为 Xiaomi 14 / synaptics_tcm_touch / /dev/input/event7。正式 com.rightpad.capture 原安装、原包名、原布局、竖屏和采集代码保持不变。游戏工具箱由原关闭开启，从游戏空间启动并实际展开后关闭局内面板，面板性能模式选中；未调整性能、触控、刷新率参数。无构建、安装、实验包恢复、Receiver 部署、重启或 Git 写操作。独立 Scheduled Task guard PID 7060 完整健康检查并确认 armed 后才改变开关。

## 方法和限制

- 只读 getevent -lt /dev/input/event7，以手机单调时间戳统计 SYN_REPORT。只比较同一次单指接触内、具有位置更新且不含接触转换的相邻报告。所有有效长间隔均保留，未按间隔大小删除。
- 用户按提示真实滑动，无自动触控样本注入。连续轮提示画圈/往返；第二轮提示慢滑、静止再移动，时间由用户手动掌握，未取得独立手指运动真值或精确阶段标记。长尾原因不能仅凭本数据归结为停顿或系统故障。
- 慢滑/静止轮包含人为静止，整轮平均频率不作为采样档位，静止附近的长间隔不作为掉点率。
- 开启前台日志为 16:06:46.624；复测接收端前快照 16:15:08.526，约 8分22秒后开始。原计划约10分钟抽查，在用户询问等待意义后提前复测，按实际时间报告。期间包含静置和两轮操作，不是持续满负荷10分钟，更不是30分钟热稳定性测试。
- 初始准备轮 off-baseline 的采集末尾发生游戏空间界面切换，标为无效严格对照，保留原始文件但不进入上表；关闭后另采 off-return 干净对照。
- 第二轮开始前最近350行日志不再包含Sender身份，检查拒绝启动，没有产生该轮原始采集。后续明确使用首轮保存的 phone-before 身份日志，要求同一手机PID、当前Receiver PID和当前Sender都一致，并保存 identity.json 说明来源；没有为此重启应用。不能把缺失启动日志解释为断连。
- 电池初始73%、33.7℃；开启测试后71%、34.2℃，未接有线/无线电源。该温度为系统电池温度，不是屏幕或SoC温度，未施加热负荷，也未测试充电干扰。
